# docs/fe-design-system 결정 기록

## 결정

- **문서의 기준 값은 현재 토큰(`index.css` `@theme`)으로 두고, 시안 값은 나란히 적어 차이만 표시했다.** 시안 8색·글자 5단계는 코드와 모두 같고, 차이는 시안에 없는 토큰과 값(그림자·모달 모서리·14px 간격)과 화면 시안의 토큰 밖 크기(21·19px 등)뿐이라, 코드를 기준으로 써야 다음 리팩터링 범위가 분명해진다. (사용자 승인)
- **정리 대상의 우선순위는 P1(규칙 위반이 보이거나 같은 UI가 서로 다르게 보임) → P2(shared로 올릴 중복) → P3(의도한 예외라 규칙에 넣을지 확인)로 정했다.** 기능·동작이나 보이는 모양이 바뀌는 항목은 우선순위와 따로 "사용자 확인"을 붙였다. 리팩터링 브랜치가 확인 없이 진행할 수 있는 범위를 나누기 위해서다. (사용자 승인)
- **roadmap.md 진행 현황은 REQ 단위 표라 브랜치 행을 넣을 곳이 없어, 표 아래에 "### 프론트 정리" 표(브랜치·내용·상태)를 새로 두었다.** (사용자 승인)
- git-workflow.md §2에는 두 브랜치를 2순위 표 끝(프론트 행 뒤)에 넣었다. 지금 단계에서 진행하는 정리 작업이라서다.
- 14px(`3.5`) 간격은 4px 단위 밖이지만 시안도 목록·안내 상자에서 같은 값을 써서 정리 대상에 넣지 않았다.
- 터치 영역(44px) 때문에 시안보다 큰 캘린더 날짜 칸, 디자인 시스템(48)과 다른 대여 상세 시안 버튼(50)은 코드 값을 유지하는 것으로 적었다.
- `mocks/`의 `#hex` 15건은 목 이미지 자리 색이라 토큰 규칙 대상에서 뺐다.
