## PR #33 리뷰 반영
- verify에서 카카오 H 항목이 없는 경우만 400 REGION_VERIFY_MISMATCH로 변환한다. 공용 카카오 클라이언트와 by-coord의 404는 유지한다.
- 소유권 조회는 변환 구간 밖에 있어 경로 id 없음·남의 동네는 404 유지. 카카오 장애 500도 변환하지 않는다.
- 비밀번호 변경 시 현재 RT family 유지·다른 기기 재발급 거절, 이전 비밀번호 거절·새 비밀번호 로그인 성공을 실제 DB·Redis·JWT 필터로 검증하는 테스트 추가.
- 동네 3개째 거절·대표 삭제 후 승계, H 항목 없음의 verify 400/by-coord 404, 소유권 404, 외부 오류 500 회귀 테스트 추가. 카카오 통신만 Mock으로 대체한다.
- open-issues.md에 팀장 결정을 기록하고 member.md에 반영했다. roadmap의 001~003만 ✅, 004·005는 기존 상태 유지.

## 구현 메모
- Redis Lua로 RT jti 비교·교체·재사용 폐기를 원자적으로 처리한다. 회원별 family Set의 TTL은 RT 이상 유지한다. 단일 Redis 전용이며 Cluster 전환 시 hash slot 재설계 필요.
- Access Token에 familyId를 넣는다. 기존 2인자 JWT/claims 생성자는 테스트 호환용이며 familyId 없는 AT로 비밀번호 변경 시 재로그인이 필요하다.
- 로그인·재발급·비밀번호 변경은 같은 회원 행 잠금으로 직렬화한다. Redis 실패 시 비밀번호 변경 DB 롤백. Redis 폐기 후 DB 커밋 실패 시 다른 기기의 재로그인이 필요할 수 있다.
- 프로필 업로드는 DB 트랜잭션 밖에서 수행한다. DB 변경 실패 시 새 파일, 커밋 후 이전 파일 정리. 삭제 실패 재시도 작업은 후속 개선 사항이다.
- 가입·닉네임 변경은 DB 고유 제약 이름을 검사해 동시 중복도 409로 변환한다.
- 동네 쓰기는 회원 행 잠금으로 직렬화하며 좌표는 저장하지 않는다. 인증은 카카오 조회 뒤 별도 트랜잭션에서 소유권을 재검증한다.
