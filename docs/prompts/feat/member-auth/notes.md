# 회원·인증 구현 작업 중

- 사용자 요청으로 이번 변경에 REQ-005(내 정보·프로필·비밀번호)를 추가했다. 동네 관리 REQ-004는 미구현이다.
- REQ-002/003: Redis Lua로 jti 비교·교체·재사용 폐기를 원자적으로 실행한다. 회원별 family Set은 RT TTL 이상 유지한다. 단일 Redis 구성 전용이며 Cluster 전환 시 키 hash slot 재설계가 필요하다.
- 실제 로그인·재발급 AT에 familyId를 넣고 인증 details에 보관한다. 기존 2인자 JWT 발급·claims 생성자는 기존 테스트 호환용이다. familyId가 없는 기존 AT로 비밀번호 변경 시 재로그인이 필요하다.
- REQ-005: 업로드는 DB 트랜잭션 밖에서 수행한다. DB 변경 실패 시 새 파일을 정리하고, DB 커밋 후 이전 파일을 정리한다. 삭제 실패는 로그로 남기며 파일 정리 재시도 작업은 후속 개선 사항이다.
- 로그인·재발급·비밀번호 변경은 같은 회원 행 잠금으로 직렬화해 이전 비밀번호를 확인한 로그인이 비밀번호 변경 뒤 뒤늦게 토큰을 저장하는 경쟁을 방지한다. Redis 장애 시 비밀번호 변경은 DB 롤백한다. Redis 폐기 후 DB 커밋 실패 시 다른 기기는 재로그인이 필요할 수 있다.
- 가입·닉네임 변경은 DB 고유 제약 이름을 검사해 동시 중복도 409로 변환한다.
- 검증 대기: 작성 환경에서 Gradle 다운로드가 네트워크 제한으로 실패했다. 사용자 환경에서 컴파일·자동 테스트·Spotless·OpenAPI 재생성이 필요하다. REQ-005 자동 테스트와 전체 회귀 테스트, roadmap 갱신 전까지 완료로 표시하지 않는다.

- REQ-004 기본 관리: 이름 검색, 내 동네 목록, 추가(최대 2개·중복 방지), 대표 변경, 삭제를 구현했다. 회원 행 잠금으로 동네 쓰기를 직렬화한다. 존재하지 않는 regionId는 400 details.regionId로 반환하기 위해 BusinessException에 선택적 details를 추가했다.
- REQ-004 미완료: 실제 행정동 마스터 데이터 적재, 카카오 좌표 조회, 위치 인증. 가짜 인증 또는 임의 좌표 데이터는 추가하지 않았다. API 문서에서 해당 두 API는 미구현 표시 유지.

## 카카오 행정동 연동 추가
- RegionLookupClient와 Kakao 구현: x=경도, y=위도, H 코드만 사용; 요청 시간 제한.
- 좌표 조회 후 별도 쓰기 트랜잭션에서 소유권·회원 상태·행정동 일치를 재검증하고 Clock으로 인증 시각 저장. 좌표 미저장.
- API 키는 기존 infra/.env의 KAKAO_REST_API_KEY 사용. 키가 없으면 해당 API만 실패하며 서버 기동은 가능.
