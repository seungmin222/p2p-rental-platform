# feat/fe-period-calendar 결정 기록

SCR-06 대여 가능 기간과 SCR-12 결제 내역 기간 입력을 브라우저 `type="date"`에서 공용 `Calendar`로 바꾼다.

## 결정

- **Calendar props**: `maxDays`에 `null`(상한 없음)을 허용하고 `hint`(아무것도 안 고른 상태 안내, 기본은 기존 "1~30일" 문구)·`startOnlyHint`(시작일만 고른 상태 안내, 기본은 기존 "{endLabel}을 선택해 주세요")·`endLabel`(기본 '반납일')을 더했다. `startOnlyHint`는 리뷰 뒤 추가: 결제 내역은 시작일만으로 적용할 수 있는데 "종료일을 선택해 주세요"가 나와 꼭 골라야 하는 것처럼 읽혔다. 기존 사용처(예약·상세·검색 필터·연장)는 그대로다. `maxDays`를 빠뜨리는 실수를 막도록 기본값은 두지 않고, "제한 없음"은 `null`을 명시할 때만이다. "예약됨 없음"은 이미 검색 필터처럼 days를 AVAILABLE/UNAVAILABLE로만 만들고 statusLabels에서 BOOKED를 빼면 되므로 새 prop을 만들지 않았다.
- **SCR-06 시트 동작**: 줄마다 입력 모양 버튼 → `PeriodCalendarSheet`(BottomSheet). 시트 안 초안은 "확인"(종료일까지 골라야 켜짐)을 눌러야 그 줄에 반영되고, 닫기·취소·시작일만 고른 상태는 버린다(반만 고른 값을 폼에 넣지 않는다). 취소·확인은 결제 내역 시트와 같게 BottomSheet `footer`에 둔다(리뷰 반영). 폼 값 형식·`validatePeriods`·추가·삭제는 그대로다.
- **days·달 범위**: 검색 필터의 `buildFilterDaysInRange`를 재사용(오늘 이전 선택 불가)하고 넘겨 볼 수 있는 달도 같은 "이번 달 ~ 11개월 뒤"다(정책 수치가 아닌 기존 UI 값). 수정 화면에서 이미 지난·더 먼 기간이 있으면 그 달까지 넓혀 미리 선택된 채로 보이고, 다시 고를 때만 오늘 이후로 고른다.
- **줄끼리 겹침**: 기존처럼 폼 전체 오류 문구만 둔다. 캘린더에 다른 줄 기간을 표시하는 기능은 만들지 않았다(범위를 작게).
- **버튼 글자**: 해를 넘기는 기간이 있어 `YYYY.MM.DD ~ YYYY.MM.DD`로 연도까지 쓴다.
- **SCR-12 결제 내역**: 오늘 이후 선택 불가, 최대 일수 없음, `maxMonth` = 이번 달. 주소의 from이 미래 날짜여도 처음 보이는 달은 이번 달 이하로 묶는다(리뷰 반영: 넘어갈 수 없는 달에서 시작하지 않게). 과거 쪽에 지어낸 한계를 두지 않으려고 `minMonth` 없이 days를 "보고 있는 달(또는 고른 시작일의 달) ~ 오늘"로 그때그때 만든다(`buildHistoryDays`).
  - 시작·종료를 고르면 그 범위, **시작일만 고르고 적용하면 to 없이 보내 시작일 ~ 오늘**(사용자 결정), 시작일만 고른 상태의 캘린더 안내는 "종료일을 고르거나, 이대로 적용하면 오늘까지 찾아요". 아무것도 안 고르면 "적용"이 꺼지고 "최근 3개월로"만 쓴다. "종료일만" 조건은 이제 주소로만 만들 수 있고, 시트를 열면 고른 것 없이 시작한다.
  - 캘린더라 순서가 뒤집히지 않아 시트용 `validateHistoryRange`는 지웠다. `HISTORY_RANGE_ORDER_ERROR`는 서버 400 안내에 남긴다.
- **PC(lg)**: 두 화면 모두 시트를 그대로 쓴다(BottomSheet가 lg에서 가운데 모달 `max-w-md`로 바뀌어 검색 필터와 같다).
- **브라우저 확인**: 앱 안 브라우저 창이 MSW 서비스 워커를 등록하지 못해 목 화면을 띄우지 못했다. 단위 테스트·lint·build로만 확인했다.
