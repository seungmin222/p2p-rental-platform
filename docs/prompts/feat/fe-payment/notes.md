# feat/fe-payment 결정 기록

## 요약
- API 연동: `POST /api/payments`, `POST /api/payments/confirm`(백엔드 변경 없음). 화면: `/payments/success`, `/payments/fail`, SCR-07 예약 후 결제창, SCR-08 결제하기, 보증금 안내 카드.
- 주요 파일: `frontend/src/features/payment/*`, `pages/PaymentSuccessPage.jsx`·`PaymentFailPage.jsx`, 목 `mocks/payment.js`·`paymentLogic.js`·`paymentScenario.js`·`rentalStore.js`.
- 남은 일: 토스 테스트 키로 결제창 왕복과 창 닫기 동작 확인(아래 "왕복 확인"). 키가 아직 없어 미확인이다.
- 남은 일: 백엔드와 대여 상세 응답 필드(보증금 상태·누적 환불액·연체료)를 합의한다. REQ-023·049 전에 `getDepositNotice`의 추정을 필드 기반으로 바꾼다. open-issues #33은 실제 백엔드 호출이 필요해 열어 둔다.
- 다음 브랜치: 실제 승인·부분 취소를 검증하려면 회원·물품 로직 머지 후 목을 끄고 전체 흐름을 다시 돌린다.

## 데모
- **데모는 전부 목 + 결제창만 실제 토스다.** 회원·물품 로직이 없어 실제 백엔드로 흐름을 돌릴 수 없다. 승인·반환은 목 응답이라 토스에 승인 건이 남지 않고, `payment.md` 원칙 6과 2순위 완료 기준을 충족하지 않는다.
- **목 응답 표시는 데모 화면에 넣지 않는다.** 앱 화면에 데모 전용 문구를 남기지 않기 위해서다. 목 응답이라는 사실은 영상 설명이나 발표에서 밝힌다.
- **초기화는 콘솔에서 `window.__mockPayment.reset()`이다.** 대여·결제 목만 시드로 돌리고 로그인은 유지한다. 탭을 닫아도 시드로 돌아간다.
- **계정 전환은 같은 탭에서 한다.** 저장소가 `sessionStorage`라 탭마다 따로다. 대여자 `user1`, 물품 101의 제공자 `user2`.
- **인계를 찍으려면 시작일을 오늘로 고른다.** 인계는 시작일부터 가능하다.
- **실패 재현은 `window.__mockPayment.failNext(code)`다.** 승인 실패 코드와 `DEPOSIT_REFUND_FAILED`를 받는다. 반환 실패 뒤에는 목에 재시도 배치가 없어 `RETURNED`에 머물므로 `reset()`한다.

## 목
- **대여 목 저장소를 `sessionStorage`에 둔다.** 결제창에서 돌아오면 페이지가 새로 떠서 메모리 저장소로는 주문이 사라진다. `failNext`도 같은 이유로 저장한다.
- **올린 사진의 `blob:` 주소는 다시 읽을 때 자리표시 이미지로 바꾼다.** 새로고침하면 죽는 주소라서다.
- **대여 목의 "나"를 AT의 회원으로 바꿨다.** 고정된 회원 1로는 새 예약의 제공자 단계(인계·상태 확인)를 진행할 수 없다. AT가 없으면 전처럼 회원 1이다.
- **시드 대여는 주문이 없어도 보증금이 있으면 동결로 본다.** 시드에 결제 행을 만들지 않기 위해서다.
- **만료는 만료 시각 + 1분(배치 주기)에 취소한다.** 그 1분 동안은 `PAYMENT_EXPIRED`, 이후는 `RENTAL_INVALID_TRANSITION`으로 백엔드와 같다.
- **목 전용 코드는 `main.jsx`의 동적 import 뒤에만 있다.** `VITE_USE_MOCK=true`로 빌드해도 번들에 없음을 확인했다. `dist/mockServiceWorker.js`는 `public/` 파일이라 빌드에 복사되지만, 등록하는 코드가 번들에 없어 쓰이지 않는다.

## 결제창
- **SDK는 `@tosspayments/tosspayments-sdk` 2.9.0이다.** 최신 2.10.0은 배포 후 2주가 안 됐다. 토스 문서의 "결제창(구버전)"이 API 개별 연동 방식이다. 결제할 때만 동적 import한다.
- **대여 상세로 `replace`한 뒤 결제창을 연다.** 뒤로 가기로 예약 화면에 돌아가 같은 기간을 다시 예약하지 않게 한다.
- **`rentalId`는 `sessionStorage`에 둔다.** 토스 복귀 값에 없고 구매자 취소는 `orderId`도 없으며, successUrl의 기존 쿼리 허용 여부가 문서에 없어서다.
- **승인 중복은 `orderId`별 진행 중 요청 공유 + 서버 멱등으로 막는다.** 승인 중 새로고침은 503 `PAYMENT_RESULT_UNKNOWN`이 될 수 있어 "다시 확인" 버튼을 둔다. 재시도 횟수 정책이 없어 자동 재시도는 하지 않는다.
- **승인 응답 200이 `APPROVED`일 때만 완료 토스트를 띄운다.** 이미 환불된 주문의 재호출은 200 + `CANCELED`다.

## 보증금 표시
- **기존 필드로만 추정해 표시한다(`getDepositNotice`, TODO).** 대여 상세에 보증금 상태·환불액·연체료가 없다. 연체료·차감이 없다는 가정이므로 REQ-023·049 전에 바꿔야 한다.
- **취소 환불액은 취소하는 순간 토스트로만 알린다.** 대여 상세로는 결제 전 취소인지 구분할 수 없다.

## 왕복 확인
- **미확인.** `frontend/.env.local`에 `VITE_TOSS_CLIENT_KEY`가 없어 실제 결제창을 열지 못했다. 복귀 주소에 직접 들어가 승인·실패 화면과 새로고침 후 저장소 복원만 확인했다.
- **결제창을 닫았을 때의 동작(Promise 거절인지 failUrl 이동인지): 미확인.** 문서에 없어 코드는 둘 다 처리한다. 키를 넣고 확인한 뒤 이 줄을 고친다.
