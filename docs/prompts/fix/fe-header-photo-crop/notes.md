# fix/fe-header-photo-crop 결정 기록

## 결정

- **PC 배치 기준을 xl(1280)에서 `lg` = 56rem(896px)으로 낮추고, PC용 `xl:`을 전부 `lg:`로 옮겼다**(`styles/index.css` `--breakpoint-lg: 56rem`, `useMediaQuery.js` `XL_MEDIA_QUERY` → `PC_MEDIA_QUERY`). 화면을 반으로 나눈 창(1920의 절반, 테두리·스크롤바를 빼면 뷰포트 약 930)에서 헤더가 사라져, 하단 탭이 없는 상세 등에서 알림·채팅으로 갈 길이 없었다. 960이 아니라 896인 이유가 이 뷰포트 폭이다. 헤더만 낮추면 896~1279에서 홈 모바일 헤더·FAB가 헤더와 겹치고 채팅방이 헤더 높이만큼 넘치며 하단 탭이 함께 보여, 헤더·하단 탭·홈·상세 2열·홈 4열·채팅방·바텀시트를 같은 기준으로 묶었다. 이름(xl=1280)과 값이 달라지지 않도록 `xl` 값을 바꾸는 대신 `lg`를 썼다(A안, 사용자 승인). 896·960·1280에서 가로 넘침·헤더 넘침 없음, 768은 모바일 배치 그대로임을 확인했다(상세 오른쪽 열 약 336px).

- **대여 상세 인계·반납 대표 사진은 4:3 상자 + `object-contain` + `bg-surface` 여백.** 넓고 낮은 상자(h-27)에 cover로 넣으면 물품 대부분이 잘려 상태를 확인할 수 없었다. 작은 썸네일 줄(44)·판정 사진(64)은 정사각형 cover 그대로 둔다(작은 크기에서 contain은 여백만 커진다). 누르면 원본을 새 탭으로 여는 동작은 유지. 이 `Photo`는 `InspectionRecords` 안에서만 쓰인다(HandoverSheet 미리보기는 `ImageUploader`라 영향 없음).

- **대여 상세 페이지 로딩 Skeleton의 사진 자리를 `InspectionRecords`와 같은 2열 `aspect-[4/3]`로 맞췄다.** `h-27` 그대로면 로딩 후 실제 4:3 사진 상자로 바뀌며 화면이 밀린다(리뷰 반영). 기준값 일치 테스트·시안 1280 문서 보강 제안은 반영하지 않았다(사용자 결정).
