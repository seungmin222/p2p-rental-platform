# 미결정·불일치 사항

명세서(v1.0)를 에이전트용 문서로 옮기면서 발견한 모순·공백이다. **팀이 결정하면 "결정"을 채우고 관련 문서를 고친 뒤 이 항목을 ✅로 표시**한다. 에이전트는 여기 걸린 영역을 작업할 때 임의로 정하지 말고 사용자에게 확인한다(단, "제안"이 있으면 그대로 진행해도 됨이라고 표시된 항목은 제안대로 구현).

| # | 영역 | 내용 | 제안 | 결정 |
| --- | --- | --- | --- | --- |
| 1 | ERD | 원본 ERD는 RENTAL–PAYMENT 1:1인데 연장(REQ-038)은 추가 결제를 만든다 (`RentalExtension.paymentId`) | payments를 1:N으로, `type=RENTAL/EXTENSION`. 보증금 상태는 RENTAL 결제에만 (erd.md 반영됨) — **제안대로 진행** | |
| 2 | ERD | `Member.trustScore`가 int인데 칭찬 항목은 +0.5 단위 | `DECIMAL(4,1)` (erd.md 반영됨) — **제안대로 진행** | |
| 3 | 연장 | 연장 추가 결제가 진행되는 동안 연장 기간을 어떻게 선점하나? 그 사이 다른 사람이 그 기간을 예약할 수 있음 | rental_extensions에 `PENDING`(15분 만료) 상태를 두고 겹침 검사 대상에 포함 | |
| 4 | API | 인계 사진 등록이 `PATCH /handover`와 `POST /inspections` 두 곳에 걸쳐 있음 | 인계 확인 = 사진 업로드 + 상태 전이를 `PATCH /handover`(multipart) 하나로. `GET /inspections`는 조회 전용 — **제안대로 진행** | |
| 5 | 결제 | 보증금 반환 실패 시 재시도 횟수, 관리자 확인 기준, 그동안 대여 상태 | RETURNED 유지, 10분 간격 최대 5회 후 관리자 플래그 | |
| 6 | 검색 | "대여 가능만 보기"의 정확한 의미 미정 | 대여 희망 기간이 있으면 그 기간 기준, 없으면 "오늘 이후 가능 기간이 남아 있고 오늘이 예약되어 있지 않음" | |
| 7 | 대여 | 연체(OVERDUE) 중인 물품에 다음 예약자가 있으면 다음 예약을 이행할 수 없음. 명세에 처리 규칙 없음 | 다음 예약자에게 알림 + 다음 예약자 단독 취소 시 전액 환불 허용 (페널티 미반영) | |
| 8 | 대여 | 1순위 단계에서 제공자가 '이상' 판정 시 처리 | 판정만 기록하고 COMPLETED (차감 흐름은 2순위) — **제안대로 진행** | |
| 9 | 정산 | 정산 HELD 트리거 "분쟁 진행 중"이 무엇인지. 보증금 보류는 거래 완료 전이라 정산 레코드가 아직 없음 | 정산 생성 후 문의(REQ-063) 분쟁 접수 시에만 HELD | |
| 10 | 정산 | "영업일 +2"의 공휴일 처리 | 주말만 제외(공휴일 무시), 보고서에 명시 | |
| 11 | API | 검색 API(`GET /api/items`) 파라미터에 기준 동네가 없음. "설정한 동네 범위 내"로 한정해야 함 | `regionId`, `range` 파라미터 추가 (비회원도 전달) — **제안대로 진행** | |
| 12 | 파일 | 이미지 업로드 방식(서버 경유 multipart vs S3 presigned URL) | 썸네일을 서버에서 만들어야 하므로 서버 경유 multipart로 시작 | |
| 13 | 취소 | 시작일 이후 "양측 동의 취소"의 구체 흐름(요청·동의·기한) | 한쪽 요청 → 상대 동의 시 취소, 요청은 48시간 후 만료 | |
| 14 | STOMP | 목적지 접두사 `/pub`, `/sub` 및 개인 큐 경로 확정 필요 | api.md 표기대로 | |
| 15 | 후기 | 칭찬 항목을 대여자용/제공자용으로 나눌지 | 공통 목록으로 시작 | |
